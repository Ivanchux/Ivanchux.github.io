Hardware y Virtualización — Guía para ASIR

HARDWARE / VMs // 2026-04-13 — Iván Brihuega

En ASIR tocas hardware desde el primer día: montar equipos, diagnosticar fallos, entender por qué una VM va lenta o por qué dos máquinas virtuales no se hablan. Esta guía cubre los componentes clave, los tipos de almacenamiento y todo lo que necesitas saber para trabajar con VirtualBox y VMware sin perderte.

1. Componentes del sistema

Antes de virtualizar hay que entender qué hay debajo. Una VM no es magia: consume CPU, RAM y disco real del equipo anfitrión.

⚡ CPU

Ejecuta instrucciones. Los núcleos (cores) permiten paralelismo. Para VMs necesitas que la CPU soporte VT-x (Intel) o AMD-V (AMD), que se activa en la BIOS.

🧠 RAM

Memoria volátil. Es el recurso que más nota cuando tienes varias VMs activas a la vez. Con 8 GB puedes correr 1-2 VMs ligeras; con 16 GB ya tienes margen real.

💾 Almacenamiento

HDD, SSD o NVMe. Los discos virtuales (.vdi, .vmdk) son archivos en tu disco real. Un SSD marca la diferencia en velocidad de arranque de VMs.

🔌 Placa base

Conecta todo. Define qué socket de CPU acepta, cuánta RAM soporta y qué puertos tiene. En servidores la placa define también la gestión remota (IPMI/iDRAC).

🌐 Tarjeta de red

NIC (Network Interface Card). Las VMs crean NICs virtuales que se asocian a adaptadores del host. Velocidad real: 1 Gbps en aula, 10/25/100 Gbps en centros de datos.

🔋 Fuente de alimentación

Convierte corriente alterna en continua. En servidores suelen ser redundantes (dos fuentes) para evitar cortes. El vataje debe superar el consumo de todos los componentes.

En el examen: CPU y RAM son los cuellos de botella más preguntados en escenarios de virtualización. Si la pregunta dice "la VM va lenta", la respuesta suele pasar por RAM insuficiente o CPU sin VT-x activado.

3. BIOS / UEFI y arranque

La BIOS (Basic Input/Output System) o su sucesor UEFI (Unified Extensible Firmware Interface) es el primer software que se ejecuta al encender el equipo. Inicializa el hardware y busca el sistema operativo.

BIOSUEFI
InterfazTexto, teclado soloGráfica, ratón
Tabla de particionesMBR (máx. 2 TB, 4 primarias)GPT (máx. 9.4 ZB, 128 primarias)
Arranque seguroNoSecure Boot
VelocidadLentaMás rápida (POST reducido)
Para instalar VMs con Linux: si el equipo usa UEFI con Secure Boot activado y la VM no arranca el instalador, desactiva Secure Boot temporalmente en la BIOS. Es el error más común en el aula.
Secuencia de arranque típica (UEFI): 1. POST — Power-On Self-Test (comprueba hardware) 2. UEFI busca el gestor de arranque en la EFI System Partition 3. Carga GRUB (Linux) o el gestor de Windows 4. El gestor carga el kernel del SO 5. El kernel monta el sistema de archivos raíz 6. Se inicia el proceso init / systemd

4. Qué es la virtualización

Virtualizar significa ejecutar un sistema operativo completo (máquina virtual) dentro de otro sistema operativo (anfitrión o host). El software que hace posible esto es el hipervisor.

TIPODESCRIPCIÓNEJEMPLOSUSO
Tipo 1
(bare-metal)		 Corre directamente sobre el hardware, sin SO anfitrión VMware ESXi, Hyper-V, Proxmox, KVM Producción, centros de datos
Tipo 2
(hosted)		 Corre sobre un SO anfitrión como una aplicación más VirtualBox, VMware Workstation Desarrollo, laboratorio, aula ASIR
Ventajas reales de virtualizar en ASIR: puedes tener un servidor Windows, un servidor Linux y un router virtual en el mismo portátil, aislados, sin afectar al anfitrión. Si algo se rompe, restauras un snapshot en segundos.

5. VirtualBox — Guía práctica

VirtualBox es el hipervisor de tipo 2 más usado en ASIR por ser gratuito y multiplataforma. Estas son las opciones que más importan al crear una VM nueva:

CREAR UNA VM EN VIRTUALBOX PASO A PASO

01 Nueva → Nombre y SO: elige el nombre, la ruta donde guardar el disco virtual, el tipo (Linux/Windows) y la versión exacta. VirtualBox ajusta los parámetros por defecto según la selección.
02 RAM: asigna la memoria. Regla práctica: mínimo 1 GB para Linux servidor, 2 GB para Linux escritorio, 4 GB para Windows. No asignes más del 50% de la RAM del host si vas a usar el anfitrión a la vez.
03 Disco virtual: elige VDI (formato nativo VirtualBox), asignación dinámica (crece según se usa) o tamaño fijo (más rápido, ocupa espacio desde el inicio). Mínimo 20 GB para Linux, 50 GB para Windows.
04 ISO de instalación: en Configuración → Almacenamiento → Controlador IDE, monta la ISO del sistema operativo. Al arrancar la VM la detectará como si fuera un DVD.
05 Instalar Guest Additions: una vez instalado el SO, ve a Dispositivos → Insertar imagen de Guest Additions. Habilita pantalla completa, portapapeles compartido y carpetas compartidas.
Configuración recomendada para Ubuntu Server en VirtualBox: RAM: 1024 MB mínimo — 2048 MB recomendado CPU: 1 núcleo mínimo — 2 núcleos para compilar Disco: 20 GB dinámico (VDI) Red: NAT para salir a internet / Red interna para lab Pantalla: 16 MB VRAM (servidor sin escritorio no lo necesita) Audio: Desactivar (innecesario en servidor)

6. Modos de red en VMs

Este es el tema que más confunde al principio. Cada modo conecta la VM de una forma diferente con el host y con otras VMs.

MODOVM → INTERNETHOST → VMVM → VMCUÁNDO USARLO
NAT ✅ Sí ❌ No (salvo port forwarding) ❌ No Acceso a internet sin configurar nada
Adaptador puente ✅ Sí ✅ Sí ✅ Sí La VM necesita una IP real de la red local
Red interna ❌ No ❌ No ✅ Sí Lab aislado: VMs que solo se comunican entre sí
Solo anfitrión ❌ No ✅ Sí ✅ Sí Acceso SSH desde el host, sin internet
Red NAT ✅ Sí ❌ No ✅ Sí (misma red NAT) Varias VMs con internet que se ven entre sí
Escenario típico de prácticas ASIR: VM servidor en "Solo anfitrión" para conectar por SSH desde el host, y un segundo adaptador en NAT para que el servidor pueda descargar paquetes. VirtualBox permite hasta 4 adaptadores de red por VM.

7. Snapshots y clones

Son las dos herramientas que más tiempo ahorran en el laboratorio.

SNAPSHOT — GUARDAR EL ESTADO DE UNA VM

QUÉ Un snapshot guarda el estado completo de la VM en un momento concreto: disco, RAM y configuración. Es como un punto de restauración.
CÓMO Máquina → Tomar instantánea (VM en ejecución o apagada). Si la tomas con la VM encendida, guarda también el estado de la RAM (más lento, más completo).
OJO Los snapshots encadenan cambios sobre el disco base. Si acumulas muchos sin limpiar, el disco virtual crece y las operaciones se ralentizan. Limpia snapshots antiguos cuando ya no los necesites.
Clon vs Snapshot: el snapshot está ligado a la VM original (comparte el disco base). El clon crea una VM completamente independiente, con su propio disco. Si necesitas distribuir la misma VM a varios alumnos, usa un clon completo.
Cuándo tomar un snapshot: ✔ Antes de instalar software nuevo o actualizar el SO ✔ Antes de una práctica de seguridad (firewall, SELinux) ✔ Antes de tocar configuración de red ✔ Al terminar de configurar una VM base (plantilla) Cuándo NO usar snapshots: ✘ Como sustituto de backup real (si el disco se corrompe, el snapshot también) ✘ Dejando 10+ snapshots encadenados sin limpiar

8. VMware Workstation

VMware Workstation Pro es el hipervisor de tipo 2 más usado en entornos profesionales. Desde 2024 es gratuito para uso personal. Comparte conceptos con VirtualBox pero tiene algunas diferencias importantes:

PrecioGratuito (GPL)Gratuito uso personal desde 2024
Formato disco.vdi (nativo), .vmdk.vmdk (nativo)
RendimientoBuenoMejor en I/O de disco y red
SnapshotsÁrbol linealÁrbol ramificado (más flexible)
Uso en ASIRMuy común (es el estándar de aula)Menos común, más en FP avanzada
Importar/exportarOVF/OVAOVF/OVA (compatible con VirtualBox)
OVA / OVF: formato estándar de intercambio de máquinas virtuales. Puedes exportar una VM desde VirtualBox como .ova e importarla en VMware (y viceversa), aunque a veces hay que ajustar la versión del hardware virtual.

9. Trucos y problemas frecuentes

La VM no arranca y aparece "VT-x is disabled": entra a la BIOS/UEFI del equipo físico y activa la opción de virtualización (Intel VT-x o AMD-V). Suele estar en la sección "Advanced CPU Configuration".
La VM va muy lenta: comprueba que no tengas más VMs activas de las que soporta tu RAM. Con 8 GB en el host, no intentes tener más de 2 VMs con 2 GB cada una activas simultáneamente.
Acceder por SSH a una VM desde el host: usa modo "Solo anfitrión". La VM tendrá una IP en el rango 192.168.56.0/24 (por defecto VirtualBox). Desde el host: ssh [email protected].
Disco virtual se ha llenado: en VirtualBox puedes ampliar el disco con VBoxManage modifyhd disco.vdi --resize 51200 (en MB). Después amplía también la partición desde dentro del SO con fdisk o el gestor de discos.

COMANDOS VBOXMANAGE MÁS ÚTILES

VBoxManage list vms # listar todas las VMs VBoxManage list runningvms # VMs actualmente encendidas VBoxManage startvm "NombreVM" --type headless # arrancar VM sin interfaz gráfica VBoxManage controlvm "NombreVM" poweroff # apagar VM forzado VBoxManage snapshot "NombreVM" take "nombre" # tomar snapshot VBoxManage snapshot "NombreVM" list # ver snapshots disponibles VBoxManage snapshot "NombreVM" restore "nombre" # restaurar snapshot VBoxManage modifyhd disco.vdi --resize 51200 # ampliar disco a 50 GB
VirtualBox en servidor sin GUI: con VBoxManage puedes gestionar todas tus VMs desde la terminal. Muy útil si instalas VirtualBox en un servidor Linux headless para tener un lab siempre encendido.
